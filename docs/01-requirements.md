# 01 · 需求

## 用户与目标

帮助企业内部员工，针对**制度或产品**问题，找到**有原文依据**的可靠答案；无法可靠作答时明确说明缺口或冲突，而不是编造。

## 输入

- 必填：自然语言问题 `question`
- 可选：对话历史 `history`（用于上下文追问）
- 合成资料：`data/documents.json`（含文档 ID、版本日期、分片正文）

## 工具

- `search_docs(query)`：检索相关文档列表（doc_id / title / preview）
- `read_chunk(doc_id[, chunk_id])`：读取原文片段

## 交付结果

| 字段 | 含义 |
|---|---|
| answer | 回答正文 |
| citations | 文档 ID + 原文片段 |
| gaps | 资料缺口 |
| status | completed / needs_confirmation / out_of_scope / incomplete |
| ask_user | 需确认时的问题 |
| trace | ReAct 步骤记录 |

## 范围

**在范围内：** 基于给定合成语料的检索、阅读、冲突披露、追问、工具失败处理。  
**不在范围内：** UI、线上部署、多 Agent、真实发布/写库、生产级 Runtime。

## 成功标准（必须验收）

1. **明确答案**：语料内唯一依据充分时，给出带引用的答案。  
2. **文档冲突**：D01（30 日）与 D02（15 日）无优先级时，列出冲突并请求确认，不得擅自选边。  
3. **资料外问题**：语料无依据时 `out_of_scope`，不编造。  
4. **改写相似问**：换表述仍能命中同一制度并正确作答。  
5. **上下文追问**：结合 history 理解「那期限是多久？」等省略问。  
6. **工具失败**：可注入失败；重试或返回明确 `incomplete`，并在 trace 中可见失败观察。

## 参考实例（题目原文对齐）

问「报销期限多久」：应同时引用 D01=30 天与 D02=15 天，请求确认适用制度；不能擅自答 15 天。仅命中 D01 且无冲突时可依 D01 回答。
